     Batch MCTS + PyTorch 训练框架改造计划

     Context

     当前使用 OpenSpiel 自带的 JAX AlphaZero 在 CPU 上训练太慢（一晚上 ~1000
     盘），模型很弱。需要自建基于 Batch MCTS + PyTorch
     的高性能训练框架，利用批量 NN 推理来大幅提升每步模拟速度。

     Othello 关键参数：
     - 棋盘: 8×8，观察张量: [3, 8, 8] (empty/black/white channels)
     - 动作空间: 65 (64 格 + pass)
     - 二人零和，完全信息，确定性

     改造策略

     保留 OpenSpiel 原有 MCTS/Bot 代码不动，新建 BatchMCTS 
     类并行存在，这样可以直接用原有测试验证正确性。

     实施步骤

     Step 1: PyTorch ResNet 模型 — train/model/othello_resnet.py

     创建新的 PyTorch 模型文件，参考 Flax 版本的架构
     (train/model/model_nnx.py)：

     - OthelloResNet(model_type, input_shape, output_size, nn_width, nn_depth, 
     seed)
       - Torso: Conv(3→width, 3×3, padding=1) + BatchNorm + ReLU + N×ResBlock
       - 每个 ResBlock: Conv(width→width, 3×3) + BN + ReLU + Conv(width→width,
     3×3) + BN + skip connection + ReLU
       - PolicyHead: Conv(width→2, 1×1) → Flatten → Linear(width, output_size)
       - ValueHead: Conv(width→1, 1×1) → Flatten → Linear(width, 1) → Tanh
     - forward(x) → (policy_logits, value)
     - inference(obs, mask) → (value, policy) — 单样本推理（mask legal actions）
     - batch_inference(obs_batch, mask_batch) → (values, policies) — 批量推理
     - save_checkpoint(step), load_checkpoint(step)
     - update(batch) — 梯度更新，返回 losses

     依赖: 仅 torch, torch.nn, numpy

     Step 2: 配置管理 — train/batch_mcts/config.py

     @dataclass
     class MCTSConfig:
         uct_c: float = 1.41
         max_simulations: int = 200
         batch_size: int = 32       # 每批虚拟线程数
         policy_epsilon: float = 0.25
         policy_alpha: float = 1.0
         virtual_loss: float = 1.0  # 虚拟 loss 值（用于 PUCT 调整）
         temperature: float = 1.0
         temperature_drop: int = 10
         verbose: bool = False

     Step 3: 优化 Node 类 — train/batch_mcts/node.py

     从 mcts.py 提取 SearchNode，为 Batch MCTS 优化：

     - 使用 __slots__ 减少内存
     - 增加 virtual_visits 字段（不影响 Q 值计算）
     - puct_value(parent_explore_count, uct_c) — 与原始一致
     - puct_with_virtual(parent_explore_count, uct_c, virtual_loss) — 加入虚拟
     loss 修正
     - q_value() → total_reward / max(explore_count, 1) （只用真实 visits）
     - best_child() — 基于 sort_key

     Step 4: Batch Evaluator — train/batch_mcts/evaluator.py

     保留原有 AlphaZeroEvaluator（JAX），新增：

     - BatchEvaluator 抽象基类：
       - batch_evaluate(states: list) → np.ndarray — 批量 value 评估
       - batch_prior(states: list) → list — 批量 policy 评估
     - PyTorchEvaluator(BatchEvaluator):
       - 封装 PyTorch 模型
       - 批量处理：收集 states → 构建 batch tensor → 一次 forward → 拆分结果
       - LRU cache 用于去重

     Step 5: Batch MCTS 核心 — train/batch_mcts/mcts.py

     在原有 MCTSBot 旁新增 BatchMCTS 类：

     batch_mcts_search(state):
         root = Node(state)

         for batch_start in range(0, max_simulations, batch_size):
             # 1. Selection: N 条虚拟线程并行选到叶子
             batch_paths = []
             batch_leaves = []
             for i in range(current_batch_size):
                 path, leaf_state = _select_with_virtual_loss(root, state)
                 batch_paths.append(path)
                 batch_leaves.append(leaf_state)

             # 2. Batch NN evaluation
             values, policies = evaluator.batch_evaluate(batch_leaves)
             # 3. Expansion: 展开叶子节点
             for leaf_state, policy in zip(batch_leaves, policies):
                 _expand(leaf_state, policy)
             # 4. Backprop: 回传真实结果，移除虚拟 loss
             for path, value in zip(batch_paths, values):
                 _backprop(path, value)

         return root

     Virtual loss 机制:
     - Selection 阶段：选中 child 后 child.virtual_visits += 1
     - PUCT 计算用 explore_count + virtual_visits 作为 N
     - Q 值仅用 explore_count 计算（保持无偏）
     - Backprop 阶段：virtual_visits -= 1，explore_count += 1，total_reward += 
     value

     Step 6: 验证脚本 — train/verify_mcts.py

     - 与原始 MCTS 对比：相同 evaluator (RandomRollout)，相同 state，确认 action
      分布一致
     - 测试 batch_size=1 时与原始 MCTS 输出完全一致
     - 测试 batch 模式下 virtual loss 不破坏正确性
     - 测试 PyTorch model evaluator 与 MCTS 集成

> 所以这个指令做了什么？解释一下                                                

● 两个步骤：

  1. .pth 文件 (sys_torch.pth)

  这是一个 Python 的路径注入机制。venv 启动时，Python 会自动读取 site-packages/
  下所有 .pth 文件，把里面的路径加到 sys.path。所以这行：

  C:\...\Python311\Lib\site-packages

  让 venv 里的 Python 也能看到系统 Python 装好的 
  torch（2.2.1+cu121），不需要重新下载。

  2. 降级 numpy (numpy==1.23.5)

  系统 torch 2.2.1 是用 numpy 1.x 编译的，但 venv 里有 numpy
  2.x。二者不兼容，虽然能跑但有警告。降到和系统一致就消除了。

  ---
  总结：torch 本身没有被拷贝或重装，只是让 venv "借"系统已装好的版本。

● 不是。replay_buffer_size / replay_buffer_reuse = 3000 控制的是每步收集多少个新
   state，不是训练量。

  训练量是 len(buffer) // train_batch_size，buffer 逐步填满、训练量逐步增长：

  ┌──────┬───────────────────┬────────────────────┐
  │ Step │    buffer 大小    │    每步训练批数    │

  └──────┴───────────────────┴────────────────────┘

● 你说得对。当前 len(buffer) // batch_size 做全量扫描，buffer 满了之后每步 93 次
   update，而 KataGo 等生产系统是固定每次训练量。

  两种方案：

  方案 A：固定更新次数（推荐）

  # 每步固定做 learn_rate // train_batch_size 次 update
  n_updates = learn_rate // train_batch_size  # 3000/128 ≈ 23，恒定
  - 训练时间每步一致
  - learn_rate 新数据 → 23 次梯度更新，比例固定
  - buffer 只是存储池，新数据进旧数据出，训练量不随 buffer 大小变化

  方案 B：按 buffer 满度阶梯增长

  fill_ratio = len(buffer) / replay_buffer_size
  n_updates = int(learn_rate // train_batch_size * fill_ratio)
  - buffer 越满训练越多，但不会无限制增长
  - 满 buffer 后也是 ~23 次

● AlphaZero 学的是 经过 temperature 处理的 visit 分布：

  的作用是控制探索——不是用来"人工放大最优解"的。

  最优解的权重是靠 MCTS 搜出来的：搜索越充分，best action 的 visit

  ├──────┼───────────┼────────────────────────┤
  │ 800  │ 95%       │ 搜索充分，分布极度集中 │
  └──────┴───────────┴────────────────────────┘

  # play_game 中：

> 我发现value loss还是下不去，l2不断增大，咨询了gpt，给了我如下回答，帮我看看我

  这是 AlphaZero / self-play 系统里非常经典的问题：                             
                                                                                
  现象：                                                                        
  - value loss 下不去                                                           
  - L2（参数范数）越来越大                                                      
                                                                                
  这通常意味着：                                                                
                                                                                
  网络正在不断增大参数幅度，                                                    
  试图拟合一个高噪声、非稳定的 value target。                                   
                                                                                
  --------------------------------------------------                            
  1. 最常见原因：Value Target 噪声太大                                          
  --------------------------------------------------                            
                                                                                
  你现在的 value target 大概率是：                                              
                                                                                
      z = final_game_result                                                     
      win = +1                                                                  
      lose = -1                                                                 
                                                                                
  问题在于：                                                                    
                                                                                
  同一个 state，                                                                
  在不同 self-play 对局里，                                                     
  可能一会赢，一会输。                                                          
                                                                                
  例如：                                                                        
                                                                                
      某局面真实胜率 = 55%                                                      
                                                                                
  那么：                                                                        
  - 有时 rollout 赢                                                             
  - 有时 rollout 输                                                             
                                                                                
  于是：                                                                        
                                                                                
      同一个输入                                                                
      target 一会 +1                                                            
      一会 -1                                                                   
                                                                                
  对于神经网络来说，                                                            
  这是非常高噪声的监督。                                                        
                                                                                
  结果：                                                                        
                                                                                
  网络会不断增大权重，                                                          
  试图“硬拟合”这些矛盾标签。                                                    
                                                                                
  于是：                                                                        
  - value loss 不降                                                             
  - L2 持续增大                                                                 
                                                                                
  --------------------------------------------------                            
  2. Replay Buffer 太小                                                         
  --------------------------------------------------                            
                                                                                
  如果：                                                                        
                                                                                
      buffer 太小                                                               
      +                                                                         
      reuse 太高                                                                
                                                                                
  会导致：                                                                      
                                                                                
      policy distribution drift                                                 
                                                                                
  即：                                                                          
                                                                                
  当前策略刚变化，                                                              
  buffer 很快被新数据覆盖。                                                     
                                                                                
  于是：                                                                        
                                                                                
      网络永远在追逐移动目标。                                                  
                                                                                
  典型现象：                                                                    
                                                                                
  - policy loss 正常                                                            
  - value loss 不稳定                                                           
  - value prediction 高频震荡                                                   
                                                                                
  --------------------------------------------------                            
  3. MCTS 太弱                                                                  
  --------------------------------------------------                            
                                                                                
  你目前：                                                                      
                                                                                
      playout = 128                                                             
                                                                                
  对于翻转棋，                                                                  
  这可能仍然偏弱。                                                              
                                                                                
  因为：                                                                        
                                                                                
  value label 的质量，                                                          
  本质上取决于 MCTS 搜索质量。                                                  
                                                                                
  如果搜索弱：                                                                  
                                                                                
      bad search                                                                
      -> bad move                                                               
      -> bad game outcome                                                       
      -> noisy value target                                                     
                                                                                
  那么：                                                                        
                                                                                
  网络根本学不到稳定 value。                                                    
                                                                                
  --------------------------------------------------                            
  4. tanh value head 饱和                                                       
  --------------------------------------------------                            
                                                                                
  很多实现：                                                                    
                                                                                
      value = tanh(linear(x))                                                   
                                                                                
  再做：                                                                        
                                                                                
      MSE(value, target)                                                        
                                                                                
  问题：                                                                        
                                                                                
  tanh 在接近 ±1 时，                                                           
  梯度会非常小。                                                                
                                                                                
  于是网络会：                                                                  
                                                                                
      拼命增大前层权重                                                          
                                                                                
  试图推动输出继续变化。                                                        
                                                                                
  结果：                                                                        
                                                                                
  - L2 爆炸                                                                     
  - loss 下降很慢                                                               
                                                                                
  --------------------------------------------------                            
  5. Policy 比 Value 容易学很多                                                 
  --------------------------------------------------                            
                                                                                
  policy target：                                                               
                                                                                
      来自 visit count                                                          
                                                                                
  特点：                                                                        
  - 平滑                                                                        
  - dense                                                                       
  - 低噪声                                                                      
                                                                                
  而 value：                                                                    
                                                                                
      只有 ±1                                                                   
                                                                                
  特点：                                                                        
  - sparse                                                                      
  - noisy                                                                       
  - high variance                                                               
                                                                                
  所以：                                                                        
                                                                                
  policy loss 往往正常下降，                                                    
  而 value loss 很难下降。                                                      
                                                                                
  --------------------------------------------------                            
  6. 翻转棋本身可能 value discontinuity 很强                                    
  --------------------------------------------------                            
                                                                                
  很多翻转棋类游戏：                                                            
                                                                                
  前期长期均势，                                                                
  后期突然翻盘。                                                                
                                                                                
  即：                                                                          
                                                                                
      value function 非常不平滑                                                 
                                                                                
  小局面变化，                                                                  
  可能导致巨大 value 变化。                                                     
                                                                                
  这种游戏：                                                                    
  value learning 会明显更难。                                                   
                                                                                
  --------------------------------------------------                            
  7. L2 变大的真正含义                                                          
  --------------------------------------------------                            
                                                                                
  L2 持续增大，                                                                 
  通常意味着：                                                                  
                                                                                
  模型正在不断增大 logits / feature scale。                                     
                                                                                
  原因通常有两个：                                                              
                                                                                
  （1）optimizer 推得太猛                                                       
      - learning rate 太大                                                      
      - weight decay 太弱                                                       
                                                                                
  （2）目标本身不可稳定拟合                                                     
      网络只能不断增大参数，                                                    
      试图拟合 noisy target。                                                   
                                                                                
  --------------------------------------------------                            
  8. 最可能的问题组合                                                           
  --------------------------------------------------                            
                                                                                
  结合你之前的信息：                                                            
                                                                                
  - 小 branching factor                                                         
  - playout 偏低                                                                
  - OpenSpiel 风格 learner                                                      
  - full sweep replay                                                           
                                                                                
  我认为最可能是：                                                              
                                                                                
      value target 噪声过大                                                     
      +                                                                         
      replay distribution 不稳定                                                
      +                                                                         
      MCTS 太弱                                                                 
      +                                                                         
      value regression 不稳定                                                   
                                                                                
  导致：                                                                        
                                                                                
  网络只能不断增大参数，                                                        
  但 loss 仍然下不去。                                                          
                                                                                
  --------------------------------------------------                            
  9. 推荐修复顺序（按优先级）                                                   
  --------------------------------------------------                            
                                                                                
  【第一优先级】                                                                
                                                                                
  改 learner：                                                                  
                                                                                
      full sweep replay                                                         
      ->                                                                        
      random replay sampling                                                    
                                                                                
  即：                                                                          
                                                                                
  不要每次遍历整个 buffer。                                                     
                                                                                
  改成：                                                                        
                                                                                
      random minibatch SGD                                                      
                                                                                
  这是现代 self-play 系统标准做法。                                             
                                                                                
  --------------------------------------------------                            
                                                                                
  【第二优先级】                                                                
                                                                                
  扩大 replay buffer：                                                          
                                                                                
  建议：                                                                        
                                                                                
      >= 100k states                                                            
                                                                                
  不要太小。                                                                    
                                                                                
  --------------------------------------------------                            
                                                                                
  【第三优先级】                                                                
                                                                                
  提高 MCTS playout：                                                           
                                                                                
  建议：                                                                        
                                                                                
      128 -> 256                                                                
                                                                                
  甚至：                                                                        
                                                                                
      512                                                                       
                                                                                
  观察：                                                                        
  - value loss 是否明显改善                                                     
                                                                                
  这是非常有效的诊断方法。                                                      
                                                                                
  --------------------------------------------------                            
                                                                                
  【第四优先级】                                                                
                                                                                
  降低 value loss 权重：                                                        
                                                                                
  例如：                                                                        
                                                                                
      total_loss =                                                              
          policy_loss                                                           
          + 0.25 * value_loss                                                   
                                                                                
  不要让 noisy value 主导训练。                                                 
                                                                                
  --------------------------------------------------                            
                                                                                
  【第五优先级】                                                                
                                                                                
  增大 weight decay：                                                           
                                                                                
  例如：                                                                        
                                                                                
      1e-3                                                                      
      或 3e-3                                                                   
                                                                                
  不要太小。                                                                    
                                                                                
  --------------------------------------------------                            
                                                                                
  【第六优先级】                                                                
                                                                                
  不要直接回归 ±1：                                                             
                                                                                
  例如：                                                                        
                                                                                
      target = 0.9 * outcome                                                    
                                                                                
  或者：                                                                        
                                                                                
      [-0.8, +0.8]                                                              
                                                                                
  减少 extreme fitting。                                                        
                                                                                
  --------------------------------------------------                            
                                                                                
  【第七优先级】                                                                
                                                                                
  考虑 value 分类：                                                             
                                                                                
  不要：                                                                        
                                                                                
      scalar regression                                                         
                                                                                
  改成：                                                                        
                                                                                
      win / draw / loss classification                                          
                                                                                
  通常稳定很多。                                                                
                                                                                
  --------------------------------------------------                            
  10. 最核心的一句话                                                            
  --------------------------------------------------                            
                                                                                
  你现在的问题，                                                                
  大概率不是：                                                                  
                                                                                
      “模型太弱”                                                                
                                                                                
  而是：                                                                        
                                                                                
  你正在用：                                                                    
                                                                                
      高噪声                                                                    
      非平稳                                                                    
      动态变化                                                                  
                                                                                
  的 self-play 数据流，                                                         
                                                                                
  强迫网络拟合一个本身极不稳定的 value target。                                 
                                                                                
  于是：                                                                        
                                                                                
  网络只能不断增大参数，                                                        
  但 value loss 始终很难真正下降。
